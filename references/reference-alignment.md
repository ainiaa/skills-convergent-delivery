# 参考基准对齐

仅当用户把一个具体项目、目录、分支或实现指定为目标变更的唯一基准，并要求对齐、保持一致、迁移或按其修改时使用。本规则不把普通链接、背景材料或可选示例升级为门禁。

## 写前门禁

在首次业务写入前：

1. 通过当前宿主实际读取基准和目标的相关文件。相关范围由用户目标决定；不得把“全量比较”扩大为无关模块，也不得只挑有利的文件。
2. 对每个相关差异冻结一项分类：`必须对齐`、`允许差异`或 `未决`。同时冻结比较范围、基准版本和目标基线。
3. 每项 `允许差异` 必须引用一条明确的用户决定；目标专有、纯技术或“看起来合理”都不能代替该决定，不得推断用户同意。
4. `未决` 差异不得由实现者自行选择。只有所有差异均已对齐或已有明确的用户决定时，才允许按冻结清单实施。

基准切换、相关范围改变或基准/目标内容变化使旧清单失效；重新读取、比较和冻结后才可继续写入。持久化功能事项使用既有 reference receipt 的 `alignment_bindings` 冻结目标、范围和差异；每项 `允许差异` 的用户决定必须同时出现在该事项冻结的 `decisions` 中。事项创建时记录范围内容快照，恢复前必须确认其未漂移；完成时提交与当前范围内容绑定的最终比较。外部 implementer 启动除回执外还必须冻结同一目标及全部允许差异的用户决定。`inline` 在交付中报告清单与实际读取结果，不新增状态文件。

## 验收

完成后重新比较同一范围。交付只允许保留已冻结且仍有理由的 `允许差异`；每项 `必须对齐` 均已对齐，且没有 `未决` 或未分类差异。再运行任务本身的真实验证；比较通过不能替代构建、测试或其他冻结验收。
