# PRD：Converge Skill Suite

## 1. 背景与目标

### 1.1 背景

现有 `converge` 同时描述执行、只读评审和长计划协调，职责边界与 frontmatter 存在冲突；它能完成单任务闭环，但尚不能可靠地让多个独立上下文按 Batch 接力，也缺少真正独立、只读的审查角色。

### 1.2 目标

- 将产品拆为 `converge`、`converge-review`、`converge-batch` 三个触发互斥的 Skill。
- 保留 PDLC 优先、第三方 TDD 降级、有限修复、证据验收和多窗口保护。
- 为高风险任务提供可验证的新鲜上下文审查，为长计划提供可恢复、幂等的顺序调度协议。
- 同时支持 Codex 与 Claude Code，并通过一次安装保持 Suite 版本一致。

## 2. 目标用户

| 用户角色 | 描述 | 核心需求 |
|---|---|---|
| 开发者 | 使用 Agent 完成功能或 Bug 修复 | 单次请求尽量闭环，结果有真实证据 |
| 评审者 | 只检查需求与 diff | 不改代码，发现有证据、可关闭 |
| 长计划执行者 | 按已有 Batch 计划连续推进 | 新上下文接力、不中途重复派发 |

## 3. 功能需求

### 3.1 功能列表

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| F-01 | 单任务执行 Skill | P0 | `converge` 仅负责一个授权代码任务 | frontmatter 与正文不再定义 plan/review 模式；PDLC 路由和现有状态 helper 继续可用 |
| F-02 | 独立只读审查 Skill | P0 | `converge-review` 输出绑定源码指纹的结构化发现 | 说明禁止写入；协议覆盖意图审查、盲审、发现指纹和关闭检查 |
| F-03 | Batch 调度 Skill | P0 | `converge-batch` 只调度，不读业务代码、不做设计 | 支持预检、上下文胶囊、有限状态机、幂等 dispatch、receipt、暂停/恢复/停止和最终验收 |
| F-04 | Suite 安装 | P0 | Codex/Claude 一次安装三个入口 | 安装、升级、卸载、版本检查的测试覆盖三个 Skill，已有路径不被误覆盖 |
| F-05 | 行为与协议测试 | P0 | 测试关键行为而非只匹配文案 | 协议/状态转换有可执行测试；现有全量检查通过 |
| F-06 | 文档与版本 | P1 | README、CHANGELOG、使用指南准确描述拆分 | 使用方式、职责、退化策略、兼容性和鸣谢完整 |

### 3.2 用户故事

1. 作为开发者，我希望普通功能和 Bug 修复只加载 `converge`，以便减少无关上下文。
2. 作为评审者，我希望用全新上下文只读检查 diff，以便降低实现者自我解释带来的偏差。
3. 作为长计划执行者，我希望每个 Batch 由新执行上下文处理，并在中断后不重复派发，以便无人值守地持续推进。
4. 作为维护者，我希望三个 Skill 共用 Suite 版本和兼容协议，以便升级后不会出现混合版本。

### 3.3 核心用例

#### UC-001：闭环实现单任务

- 前置条件：用户授权修改代码；工作区可获取 writer lease。
- 主要流程：冻结范围 → 选择 PDLC/TDD → 实现 → 按风险审查 → 新鲜验证 → 回执。
- 后置条件：结果可用或进入明确阻塞终态。

#### UC-002：独立审查

- 前置条件：提供验收项、基线和待审 diff 指纹。
- 主要流程：新上下文读取最小材料 → 输出结构化发现 → 主执行者验证并关闭问题。
- 后置条件：审查结果绑定源码指纹；任何后续无关生产代码修改使其陈旧。

#### UC-003：顺序执行 Batch

- 前置条件：计划包含有限 Batch、依赖、验收和最终集成检查。
- 主要流程：全量预检 → 生成当前胶囊 → 唯一派发 → 校验 receipt → 下一批 → 整体验收。
- 备选流程：暂停、恢复、停止或阻塞；无法确认派发结果时不得自动重派。

## 4. 非功能需求

- 正确性：状态转换和 receipt 校验由确定性脚本完成。
- 安全性：reviewer、scheduler 默认只读；发布、推送、删除和外发仍需用户授权。
- 可恢复性：原子写入、revision 校验和唯一 dispatch 标识避免并发覆盖与重复执行。
- 成本：简单任务不加载 review/batch 资料；只在高风险或明确长计划时启用额外能力。
- 兼容性：现有 Schema v5 单任务状态继续可读；新 Batch 状态使用独立 Schema，不混用。

## 5. 不在范围内

- 自建通用 Agent 平台、消息队列或后台守护进程。
- 自动 push、发布、合并或回滚提交。
- 为每个第三方 TDD/Review Skill 创建独立用户 Skill。
- 在宿主没有任务/子代理能力时伪造独立上下文；此时只生成可手工接力的胶囊并明确降级。

## 6. 依赖与约束

- 保持 Python 3.9+、Bash、标准库实现，不引入新依赖。
- 复用现有 `delivery_lease.py`、`delivery_state.py` 和安装锁模式。
- 三个 Skill 使用同一个 `VERSION`；review、batch receipt 使用独立协议版本。
- 现有用户脏改动和运行中状态不得被迁移脚本静默覆盖。

## 7. 验收标准

1. 三个 Skill 均有有效 frontmatter、互斥触发描述和对应 UI 元数据。
2. `converge-review` 明确只读，输出协议包含源码新鲜度、证据、问题指纹和关闭规则。
3. `converge-batch` 的状态脚本拒绝非法跳转、陈旧 revision、变更后的计划指纹和重复 dispatch。
4. Batch receipt 必须绑定 Batch、dispatch、源码树和验收证据；整体完成前必须存在计划级验收通过证据。
5. 安装器在 Codex 与 Claude Code 下同时安装/卸载三个入口，冲突时不留下部分 Suite。
6. 原有单任务 engine、lease、state、reporting 测试继续通过。
7. README、CHANGELOG、使用指南与实现一致，最终报告包含总轮数、修复问题和结果。
