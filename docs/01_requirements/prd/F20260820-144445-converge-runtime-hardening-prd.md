# PRD：Converge 运行时闭环增强

## 1. 背景与目标

Converge Suite 已具备单任务、只读审查和 Batch 状态协议，但真实跨任务调度、运行时 E2E、安装完整性诊断和最终报告仍部分依赖 Agent 自觉。本功能在不新增第四个 Skill、后台服务或外部依赖的前提下，把这些关键边界变成可执行协议和确定性检查。

目标：降低人工关注和误报完成概率，让安装、调度、恢复和汇报都能给出可核对结果。

## 2. 目标用户

| 用户角色 | 核心需求 |
|---|---|
| 日常开发者 | 普通实现尽可能自动触发并稳定闭环 |
| 长计划执行者 | Batch 能在 Codex/Claude 运行时明确派发、等待和恢复 |
| Suite 维护者 | 一条命令识别残缺安装并得到可复现 E2E 证据 |

## 3. 功能需求

| 编号 | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| F-01 | Batch 运行时适配协议 | P0 | Codex 和 Claude 分别定义能力探测、派发、等待、恢复、receipt 与降级边界；不新增用户 Skill |
| F-02 | 可执行前向 E2E | P0 | 自动测试覆盖路由隔离、PDLC 委托、两批接力、重复派发保护和中断恢复；真实 Agent 验证另留独立证据 |
| F-03 | Suite doctor/version | P0 | `--doctor` 检查三个入口、同源、依赖和引擎；`--version` 对残缺安装显示 incomplete |
| F-04 | 确定性报告器 | P0 | 从合法 Schema v5 state 生成稳定 JSON/text，准确输出终态、轮数、修复数、待处理项和验收摘要 |
| F-05 | 触发增强 | P1 | frontmatter 覆盖常见实现/修复表达；提供只读可复制的 AGENTS 片段，不自动修改用户配置 |
| F-06 | 文档和版本 | P1 | README、使用指南、CHANGELOG、测试文档和 VERSION 一致 |

### 用户故事

1. 作为开发者，我希望安装诊断能直接指出缺失的子 Skill，而不是只显示一个误导版本号。
2. 作为计划调度者，我希望不同宿主的派发和恢复动作有明确契约，避免 Agent 自由发挥。
3. 作为负责人，我希望最终报告的轮数和问题数由状态生成，而不是靠模型回忆。
4. 作为维护者，我希望发布前能自动复验关键行为，并明确区分模拟 E2E 与真实 Agent E2E。

## 4. 非功能需求

- Python 3.9+、Bash 和标准库实现，不增加依赖。
- 简单单任务不加载 Batch 适配文档，保持渐进式披露。
- doctor 和报告器只读，不获取代码写锁、不修改运行时。
- 所有自动重试有限；派发结果不确定时阻塞。

## 5. 不在范围内

- 不实现后台守护进程、消息队列或通用 Agent 平台。
- 不自动编辑全局或项目 AGENTS.md。
- 不保证宿主对任意自然语言 100% 自动触发 Skill。
- 不自动 push、merge、release 或删除状态。

## 7. 验收标准

1. 新行为先有有效失败测试，随后全部通过。
2. 现有 engine、lease、state、Batch 和 installer 测试无回归。
3. 三个 Skill 通过官方结构校验。
4. 独立 reviewer 的有效 finding 完成有限 closure。
5. 文档不得把模拟运行时测试写成真实宿主 E2E。
