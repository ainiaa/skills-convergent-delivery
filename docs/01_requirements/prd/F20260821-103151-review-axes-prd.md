# Review 双轴与集成审查 PRD

## 背景与目标用户

Converge 的任务审查需避免需求符合性与代码质量互相掩盖。目标用户是执行冻结计划的控制器与只读 reviewer。

## 目标

为每个任务依次执行 spec、quality 两个独立审查轴，并在全部任务通过后执行一次只覆盖跨任务风险的 integration 审查。

## 用户故事

1. 作为控制器，我要先得到 spec 结论，再允许 quality 审查。
2. 作为 reviewer，我要输出独立轴结果，使一个轴不能抵消另一个轴的 finding。
3. 作为计划执行者，我要让每轴最多修复一次、复核一次，并在重复问题或无进展时停止。
4. 作为旧调用方，我要继续提交 v1 intent、blind 和 closure 请求。

## 功能清单

- P0：Review Protocol v2 表达 `spec|quality|integration` 轴和轴独立结果。
- P0：编排契约固定 `spec -> quality` 顺序及每轴 `1 repair + 1 re-review` 预算。
- P0：相同 finding 指纹重复或源码指纹无变化立即 blocked。
- P0：全部任务双轴通过后才执行一次仅覆盖跨任务风险的 integration 审查。
- P0：v1 intent、blind、closure 保持可读，不自动推断新轴。

## 验收标准

1. 聚焦契约测试可验证双轴顺序与结果隔离。
2. 聚焦契约测试可验证固定预算和两种无进展阻塞条件。
3. 聚焦契约测试可验证 integration 门禁与 task-local 排除规则。
4. 聚焦契约测试可验证旧请求兼容规则。

## 非功能要求

只修改冻结任务 owned paths；不引入依赖；reviewer 继续只读；不运行最终全仓 check。

## 不在范围内

不实现通用状态机、自动修复器、发布流程或新的计划。
