# PRD：Converge 计划化执行

## 1. 背景与目标

### 1.1 背景

长上下文中一次性准备需求、设计、测试和实现，可能导致模型长时间没有工具调用或用户可见进度。Converge 还需要保持既有边界：PDLC 负责完整开发流程，Converge 只负责外层控制。

### 1.2 目标

- 实现前先形成有限、可验证的执行计划，识别依赖和潜在并行候选，再由当前 Batch v1 稳定逐项执行。
- PDLC 可用时整体委托，不拆解或复制其内部阶段。
- 对无响应、重要决策、计划偏移和未完成项给出确定的处理规则。
- 将全部能力作为一个版本交付，统一安装、文档和验证。

## 2. 目标用户

| 用户角色 | 描述 | 核心需求 |
|---|---|---|
| 开发者 | 使用 Codex 或 Claude Code 完成功能 | 少介入、少轮次、持续看到有效进展 |
| Skill 维护者 | 维护 Converge Suite | 职责清晰、行为可测试、避免重复状态机 |
| 长任务调度者 | 执行多步骤计划 | 可恢复、不会重复派发、完成情况可核对 |

## 3. 功能需求

### 3.1 功能列表

| 编号 | 功能 | 优先级 | 描述 | 验收标准 |
|---|---|---|---|---|
| F-01 | 计划职责 | P0 | 新增只负责计划生成与校验的 `converge-plan` | Suite 安装后存在四个职责互斥的 Skill |
| F-02 | PDLC 委托屏障 | P0 | PDLC 被选中后整体交给新执行上下文 | 计划中只有一个 `pdlc-run` 任务，禁止生成 native TDD 或拆 PDLC 阶段 |
| F-03 | 计划契约 | P0 | 每项有目标、范围、依赖、原子步骤和验证 | helper 拒绝缺字段、重复 ID、循环依赖并识别路径冲突 |
| F-04 | 执行选择 | P0 | 根据规模、依赖、文件重叠和上下文选择当前、全新或 Batch 执行 | 相同输入得到确定性执行模式；Batch v1 保持可恢复的顺序执行 |
| F-05 | 决策门禁 | P1 | 可逆技术决策自动记录；业务/公共契约/不可逆决策只问一个问题 | 文档明确分类、推荐默认和单问题规则 |
| F-06 | 无响应保护 | P0 | 用软探测、硬中断和原任务恢复避免假死与重复派发 | 仅在无活动且无运行进程时触发；同一任务最多自动恢复一次 |
| F-07 | 完成审计 | P0 | 对照计划、diff 和证据标记完成度与越界 | audit 输出 DONE/PARTIAL/NOT_DONE/CHANGED 和 scope drift |
| F-08 | 单版本交付 | P0 | 一次更新安装、README、CHANGELOG 和版本 | 全量检查通过且版本信息一致 |

### 3.2 用户故事

1. 作为开发者，我希望复杂任务先拆成短步骤，以便持续得到进展而不是等待一个大块生成。
2. 作为 PDLC 用户，我希望 Converge 只委托完整 PDLC 流程，以免出现两套需求、TDD 和 review。
3. 作为维护者，我希望计划结构和完成审计可由脚本验证，以便行为不只依赖提示词。
4. 作为多任务用户，我希望仅在安全时并行，失败时恢复原任务而不是重复创建执行者。

### 3.3 核心用例

#### UC-001：PDLC 可用

- 前置条件：引擎选择结果为 `pdlc-v1`。
- 主要流程：创建单任务计划 → 保存委托回执 → 全新上下文执行完整 PDLC → Converge 汇总证据。
- 备选流程：无法取得可恢复的执行引用时阻塞或手工交接，不在当前上下文模拟 PDLC。

#### UC-002：PDLC 不可用

- 前置条件：选择第三方 TDD 或 native 引擎。
- 主要流程：选择可用计划提供者 → 校验计划 → 按依赖和文件范围执行 → 完成审计。
- 备选流程：复杂且冲突的高风险方案才启用计划仲裁；普通任务不增加审查轮次。

## 4. 非功能需求

- 性能：每个执行步骤应有一次可观察的工具调用、状态更新或进度说明；不进行无界循环。
- 安全：不扩大授权，不自动发布、推送、删除或执行不可逆动作。
- 可用性：宿主不支持并行或恢复时使用顺序/手工交接，不能伪造能力。
- 兼容性：Python 3.9+；Codex 与 Claude Code 共用同一源码和协议。

## 5. UI/UX 需求

- 默认最终报告保持简洁，说明结果、验证、轮数、修复数和待处理项。
- 内部计划术语仅在详细报告中展示。
